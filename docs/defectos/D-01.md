# Reporte de defecto

**Id:** D-01
**Título:** Un número de 20 cifras en cualquier formulario da error 500 (OverflowError de SQLite)
**Reportado por:** Alejandra Vargas Baquero · **Fecha:** 2026-11-27

## Pasos para reproducir

1. Iniciar la aplicación con una base vacía: `python -m flask --app app.web run`.
2. Abrir http://127.0.0.1:5000/inventario.
3. En «Registrar medicamento» escribir el nombre `Jarabe de prueba` y el mínimo `99999999999999999999`, y pulsar Guardar.

## Resultado esperado

Regla del escenario 2 de HU-05: un mínimo que no se puede guardar «no se guarda y se muestra un mensaje». Requisito de la semana 6: el usuario no debe ver un error interno.
Se espera la pantalla de inventario con un mensaje de error y sin medicamento nuevo.

## Resultado obtenido

`500 Internal Server Error`. En la consola:

```
OverflowError: Python int too large to convert to SQLite INTEGER
  File "app/datos/repositorio.py", line 71, in guardar_medicamento
```

Pasa lo mismo al cambiar el mínimo, en la cantidad de un lote y en el id del medicamento del formulario de lotes.

## Entorno

Python 3.13, Flask 3.1.3, SQLite de la librería estándar. Rama `main`, commit `839731f`.

## Evidencia

Prueba `test_d01_numero_enorme_muestra_mensaje_y_no_da_error_500` en `tests/test_pantallas.py`: en el commit `9d86a6a` falla en sus 4 casos.

## Clasificación

**Severidad:** Media. La aplicación no se cae y no guarda datos malos, pero el dueño ve una página de error sin explicación.
**Prioridad:** Media. Es poco probable escribir 20 cifras, pero pasa con un error de digitación (por ejemplo, la tecla pegada).

## Análisis

**Caso mínimo:** `guardar_medicamento(con, "Jarabe", 10**20)`.
**Causa:** `validar_minimo` acepta cualquier entero ≥ 0, pero un INTEGER de SQLite tiene 8 bytes con signo (máximo 2⁶³ − 1). `sqlite3` lanza `OverflowError`, que no es `ValueError`, así que las rutas no lo atrapan.

## Corrección

**Commit:** `9776ce7` · **Prueba que lo protege:** `test_d01_numero_enorme_muestra_mensaje_y_no_da_error_500`

En `app/datos/repositorio.py` se agregó `_exigir_rango`: antes de guardar, el mínimo, la cantidad y el id deben caber en un INTEGER de SQLite. Si no caben, se lanza `ValueError` con «El número es demasiado grande para guardarlo», y la ruta lo muestra como cualquier otro mensaje. La regla no se puso en `app/reglas/` porque el límite viene de SQLite, no de HU-05.
